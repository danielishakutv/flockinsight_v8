# Platform review — 18 August 2026

Everything below was built, run and verified against a **production build** on
this machine before being committed. Test counts are real runs, not estimates.

---

## 1. Deploy this

```bash
cd /home/flockinsight/app
git pull && pnpm install --prod=false && pnpm db:migrate && pnpm build && pm2 restart flockinsight
```

`pnpm db:migrate` is **required** — three new migrations. All three are purely
additive (`CREATE TABLE`, `ADD COLUMN`, `CREATE INDEX`); none drop or rewrite
existing data:

| Migration | What it adds |
| --- | --- |
| `0051_growth_leads_and_outreach` | `lead`, `lead_activity`, `outreach_campaign`, `outreach_recipient` |
| `0052_denominations` | `denomination` table + `church.denomination_id` |
| `0053_church_denomination_index` | index on `church.denomination_id` |

Nothing else about the deploy changes. `scripts/backup.sh` dumps the whole
database, so the new tables are backed up from the first run without edits.

## 2. Security

### Fixed

**Spreadsheet formula injection in every CSV export (was: real, unfixed).**
A member, lead or form response named `=HYPERLINK("http://evil","Click")`
became a live formula in whatever Excel opened the export. Fixed once in
`src/lib/csv.ts`, so all nine export routes are covered — members, giving,
communication history, form responses, subscribers, leads and the rest.
Plain numbers are deliberately left alone so `-500` in a giving export is still
a number Excel can sum; only non-numeric cells starting with `= + - @ tab CR`
get the neutralising apostrophe. 10 tests cover it, including a full
export → parse → re-import round trip.

**Dependency advisories: 22 → 10.** Upgraded `next 16.2.7 → 16.2.12` and
`better-auth 1.6.14 → 1.6.30` (both patch-level, no API changes), and pinned
`postcss` to 8.5.26. This clears every Next.js advisory — including the App
Router **middleware/proxy bypass** and two **SSRF** issues — and the Better Auth
**account-takeover via pre-account linking**. Those were the four that mattered.

Because auth is the thing you cannot afford to break, it was re-verified
end-to-end after the upgrade: login, session persistence across reloads, wrong
password rejected, anonymous visitors bounced off `/superadmin`, the leads CSV
export not being public, superadmin impersonation, and sign-out actually
clearing the session. All pass.

### Still open, deliberately

| Package | Severity | Why it's left | 
| --- | --- | --- |
| `nodemailer` | high | Needs a **major** upgrade (8 → 9). The advisory is about the message-level `raw` option; `src/lib/mailer.ts` never uses it, so we aren't exposed. Worth doing in daylight with the SMTP path tested, not overnight. |
| `sharp` | high | Comes from Next's image optimiser. **`next/image` is not used anywhere in this codebase** (checked), so the code path is inert. |
| `esbuild`, `postcss`(nested), `dompurify` | mod/low | Build-chain and PostHog-internal. Not reachable at runtime by a visitor. |

### Checked and fine

- Security headers (HSTS, nosniff, SAMEORIGIN, referrer policy, permissions
  policy) are applied to every response; `poweredByHeader` is off.
- `/superadmin/**` is protected twice — the proxy matcher redirects without a
  session cookie, and `requireSuperAdmin()` runs in the layout and in every
  server action.
- The new public `/demo` form has a honeypot, a per-10-minute flood guard, and
  de-duplicates against existing leads, so it can't be used to spam the pipeline.
- Backups are a whole-database `pg_dump`, AES-256 encrypted, 15 kept locally
  plus an off-site rclone copy.

## 3. What's new

### Platform admin, redesigned

The admin used to wear the church app's clothes: 36px extrabold titles, big
cards, and a 16-item pill bar that scrolled sideways. It's now its own thing.

- **A grouped sidebar** — Platform / Customers / Growth / Content & ops — so
  sixteen links read as four jobs. Longest-match highlighting means
  `/growth/outreach` lights *Outreach*, not *Pipeline*. On phones it's a drawer
  behind one button, and it closes when you navigate.
- **A calmer type scale**: page titles 20px semibold instead of 36px extrabold,
  descriptions 13px, card titles 14px. Applied across all 16 pages.
- **Denser chrome** via a single `data-admin` scope in `globals.css`: tighter
  card padding, no drop shadows, smaller radii and control heights. The
  church-facing app is untouched — it stays big and friendly on purpose.

### Denominations

- Create, rename, archive and **merge** denominations (merge moves the churches
  and archives the duplicate — nothing is deleted, so old names still read).
- Add existing churches to one from the denomination page (multi-select with
  search), or from the church's own admin page.
- **"N churches already say they belong here"** — churches whose own typed
  denomination text matches are detected and can be added in one tap.
- Assigning also updates the church's own public label, so the directory and
  public pages keep working with no second edit.
- **Outreach can now target a whole denomination** — the point of grouping.

### Growth (from yesterday, now denomination-aware)

Lead pipeline, follow-up dates, timeline, CSV import/export, and email/SMS
outreach with per-recipient delivery records.

## 4. Fixed along the way

  word must appear somewhere, in any order — the same rule the dropdown search
  uses.
- **Page title disagreed with the nav** (`Growth` vs `Pipeline`). Now both say
  Pipeline.

### One thing to know about `pnpm lint`

It reports 10 errors. **All 10 are pre-existing and in files this work never
touched** — theme toggles, the date-time widget, push-toggle, setup notices,
the accept-invitation page. I verified this by reverting to the old
`package.json`/lockfile and re-running: the same 10 appear. They are
lint-rule opinions (mostly the standard "set mounted in an effect" hydration
pattern), not defects; `next build` does not run them and they have no runtime
effect. Worth a tidy-up pass in daylight, not a 2am refactor of working code.

## 6. Recommended next, in order

1. **Referral codes on signup.** The highest-yield unbuilt growth lever: your
   existing pastors each know 20 more. Credit the referrer's wallet.
2. **A daily digest of due follow-ups** (email or WhatsApp, 7am). The pipeline
   should chase you, not the other way round.
3. **Get the crons actually running.** The command centre currently reports
   eight jobs that have *never run* — reminders, birthdays, storage billing,
   scheduled broadcasts, devotionals, first-timer follow-up, trial reminders.
   Every one of those is a feature churches are paying for but not receiving.
   This is the single biggest gap on the platform and it is a crontab, not code.
4. **Restore-test a backup** into a scratch database once a quarter, and alert
   if the off-site copy fails. A backup you have never restored is a hope.
5. **nodemailer 8 → 9** with the SMTP path tested.
